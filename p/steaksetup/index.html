blog搭建碎碎念

stack的一些问题

网络上搭建blog的教程很多都有点过时了，而我恰好选择了stack这个未完善的theme作为我网站的主题，搭建的时候也因为不知道应该干什么，没有目的的去翻文档，汉化翻的也是一坨，浪费了很多时间，现在想来像这种改一点配置就会有明显影响且各个影响之间没有什么关联的项目完全可以放心的交给ai，每一个配置的更改在前期都十分让我感到有趣，也能学到一些很有意思的文件结构比如原先的单配置文件现在被放在了一个文件夹下，但是主题虽然是新的可是它并不适配任何版本的hugo由于两者开发不是同时的，stackv4运用了老版本hugo存在的变量，但是没发现在新版本变量在部署的时候不存在，导致我部署的时候一直报错调了十几次才改好，这就是很常见的没有交流的协作问题，不过这也很正常是人就会犯错这也是开源社区的意义所在。

github静态网页动态上传的配置问题

我到部署的时候才发现仓库名是用户名.github.io会部署成去掉github前缀的网址导致配置网址的时候一直有问题，用action动态上传的时候秘钥的配置也很迷，要记得开读写权限，最开始用PAT秘钥失败了改为用Deploy Key才成功。

经验总结

通用经验

  1. 代码的编写还是重实践不能上来什么都不了解就看文档，文档可以带来规范的写法，但是不能解决疑难问题，而像blog搭建这种纯粹在疑难问题上面浪费时间，很多变量不是刚需了解的任务，文档的作用确实不会很大。
  2. 遇到问题查询网络上存在的解法很好但是大多解法都具有时效性，要么版本降级要么头铁和问题硬干。
  3. 版本适配是项目使用时特别关键的一个问题，在下载前最好先了解当前项目适配的软件的最低与最高版本避免在版本兼容问题上浪费时间
  4. github秘钥的配置
    1. PAT秘钥的配置:在setting的secrets and variables选项中点击 New repository secret 创建获得秘钥复制到你需要拥有权限的仓库，优点是方便，缺点是太方便了安全性低，可以调整颗粒度与减短过期时间来增加安全性，但是没这个必要，主要PAT有时候会不稳定像我配blog的时候就失败了。
    2. Deploy Key：在目标文件夹中打开cmd，输入
      1

      ssh-keygen -t ed25519 -C "hugo-blog-deploy" -f hugo-deploy
      按两次回车后会在文件夹下创建一对秘钥，公钥放进目标项目的deploy key，私钥放进和PAT需要权限的仓库的一个地方，记得把秘钥本地保存或者删掉而不是上传到github的公开仓库
